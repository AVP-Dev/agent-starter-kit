# Agent Starter Kit: Инженерный стандарт разработки с ИИ (2026)

[English Version](README.md) | **Русская версия**

[![Verification Gate](https://github.com/AVP-Dev/agent-starter-kit/actions/workflows/verification.yml/badge.svg)](https://github.com/AVP-Dev/agent-starter-kit/actions/workflows/verification.yml)

Стартер-кит помогает адаптировать инженерные рекомендации и автоматические проверки к новому или существующему проекту. Шаблоны написаны на русском языке. Их можно перевести при онбординге.

- [AGENTS.md](https://agents.md/) служит основным файлом инструкций. Порядок загрузки зависит от инструмента и настроек.
- Claude Code начиная с v2.1.277 поддерживает прямую загрузку. Для окружений, которым нужен `CLAUDE.md`, флаг `--with-claude` добавляет файл с импортом `@AGENTS.md`. [Документация Claude Code](https://code.claude.com/docs/en/memory#agentsmd)

## Инженерные рекомендации

- **Учитывай соглашения проекта.** Сохраняй существующую архитектуру и практики. Рассматривай [Skeleton + Pluggable Modules](docs/architecture.md), когда такие границы подходят задаче. Для UI опирайся на дизайн-систему проекта.
- **Соизмеряй проектирование с риском.** Для локальной правки достаточно цели, инварианта и проверки. Для изменений контрактов и сложных сценариев сбоев используй применимые части [DESIGN-манифеста](docs/design-manifest-template.md). Согласуй изменение владения данными, прав доступа, контрактов безопасности или необратимое действие.
- **Проверяй затронутое поведение.** Сравни результаты с исходным состоянием. Укажи новые регрессии, исходные падения и проверки, ограниченные окружением. [Руководство по верификации](docs/verification.md)
- **Выполняй Git-операции явно.** Проверяй remote, когда от него зависит интеграция. При недоступном remote продолжай локальный анализ. Следуй процессу проекта для коммитов, добавляй в индекс явные пути и избегай слепого pull.
- **Учитывай версии зависимостей.** Сверяй синтаксис с Context7 или официальной документацией для установленной версии. Согласуй миграцию, если задача требует несовместимого обновления.
- **Выбирай способ работы под задачу.** Делегируй независимые части, если это помогает. Сохраняй checkpoint перед передачей работы, паузой или после значимого этапа. Используй число строк и длину отчёта как ориентиры. [Маршрутизация](docs/agent-routing.md) · [Структура проекта](docs/project-structure.md)

## ⚡ Максимально автоматический онбординг (Zero-Friction)

Вам **не нужно вручную описывать проект** или заполнять спецификации. Агент сделает это по протоколу [docs/onboarding-protocol.md](docs/onboarding-protocol.md) в автоматическом, полуавтоматическом или ручном режиме.

### Сценарий А: Автоматический brownfield

Отправьте агенту:

> **Промпт для агента:**
> ```text
> Выполни протокол онбординга из docs/onboarding-protocol.md.
> Изучи текущий репозиторий, определи Brownfield, извлеки фактический стек,
> структуру, команды проверки и существующие документы.
> Подготовь неразрушающее обновление AGENTS.md и docs/.
> Не задавай вопросы о фактах, которые видно из файлов.
> Покажи отчёт о найденном, сохранённом, добавленном и требующем решения.
> ```

### Сценарий Б: Новый greenfield-проект

> **Промпт для агента:**
> ```text
> Выполни протокол онбординга для нового проекта.
> Определи неизвестные развилки, задай только необходимые вопросы с
> рекомендациями, затем заполни документацию подтверждёнными значениями.
> Покажи итоговое резюме перед применением необратимых изменений.
> ```

### Сценарий В: Безопасная подготовка через `init-project.sh`

```bash
/path/to/agent-starter-kit/scripts/init-project.sh --yes /путь/к/новому-проекту
/path/to/agent-starter-kit/scripts/init-project.sh --dry-run /путь/к/проекту
/path/to/agent-starter-kit/scripts/init-project.sh --update /путь/к/существующему-проекту
/path/to/agent-starter-kit/scripts/init-project.sh --with-claude /путь/к/существующему-проекту
```

Скрипт добавляет только отсутствующие файлы, не перезаписывает существующие `AGENTS.md`, `CLAUDE.md`, `.gitignore`, `docs/*` и инструменты в `scripts/`, а затем передаёт проект агенту для сканирования и заполнения. В целевой проект попадают универсальный dispatcher, baseline scanner и шаблон профиля; активный профиль агент создаёт по манифестам. Workflow стартер-кита проверяет этот репозиторий. Команды подключаются к CI целевого проекта отдельно. `--update` предназначен только для существующего проекта и не создаёт новый каталог.

### Сценарий Г: Ручной режим

Агент может подготовить поля для ручного заполнения. Ручные значения имеют приоритет и не заменяются автоматически.

## Примеры технологий

Для нового проекта оцени применимость инструментов и проверь поддерживаемые версии. Для существующего проекта бери стек и версии из манифестов и lockfiles.

- **Среда выполнения:** Node.js / Bun / Python / Go / TypeScript
- **Фронтенд:** React / Next.js (App Router) / Astro / Tailwind CSS
- **Бэкенд:** Next.js Server Actions / FastAPI / Go microservices / WebSockets / BullMQ (Redis)
- **Базы данных:** PostgreSQL, Drizzle ORM, Redis
- **AI & RAG:** LLM APIs (Anthropic Claude, OpenAI GPT, Gemini), pgvector + HNSW, ONNX Runtime
- **Инфраструктура:** Docker, Coolify / Dokploy (PaaS), GitHub Actions (CI/CD), Linux (Bash, Nginx)
