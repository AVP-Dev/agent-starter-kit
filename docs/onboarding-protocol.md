# Автоматический протокол онбординга проекта (Agent Onboarding Protocol)

> **Назначение документа:** Этот протокол читает любой ИИ-агент (**Gemini Antigravity**, **Claude Code**) при первичном подключении к новому или существующему проекту (включая сложные монорепозитории).
> Протокол инструктирует агента, как **автоматически просканировать кодовую базу, синтезировать контекст и заполнить документацию**, не разрушая существующие файлы.

---

## 🤖 Как запустить онбординг (Команда для человека)

Просто отправьте вашему агенту один из следующих запросов:

### Вариант 1: Если стартер-кит лежит в отдельной папке на компьютере
```text
У меня есть стандарт разработки в папке /path/to/agent-starter-kit (или ~/work/agent-starter-kit).
Изучи инструкцию в /path/to/agent-starter-kit/docs/onboarding-protocol.md.
Просканируй текущий проект, перенеси и настрой необходимые стандарты и заполни AGENTS.md без удаления существующей документации. Покажи мне результат на подтверждение.
```

### Вариант 2: Если стартер-кит уже скопирован в проект (через init-project.sh)
```text
Выполни протокол онбординга из docs/onboarding-protocol.md:
Просканируй проект, определи реальный стек, рабочие команды тестов и линтеров, синтезируй описание и актуализируй AGENTS.md и документацию в docs/.
```

---

## 📋 Инструкция для ИИ-агента (Алгоритм выполнения)

При получении запроса на онбординг агент обязан строго последовательно выполнить следующие 4 фазы:

---

### ФАЗА 1. Исследование кодовой базы (Discovery Phase)

1. **Определение типа репозитория:**
   - Монорепозиторий (pnpm-workspaces, Turborepo, Nx, Lerna, Cargo workspace, Go workspace)?
   - Одиночное приложение (Single SPA, backend API, microservice)?
   - Составные части (`apps/*`, `packages/*`, `services/*`, `frontend/`, `backend/`).

2. **Анализ манифестов зависимостей и версий (Truth from Lockfiles):**
   - Node.js / Bun: `package.json`, `pnpm-lock.yaml`, `bun.lockb`, `package-lock.json`.
   - Python: `pyproject.toml`, `poetry.lock`, `Pipfile`, `requirements.txt`.
   - Go: `go.mod`, `go.sum`.
   - Docker / Infra: `Dockerfile`, `docker-compose.yml`, `coolify.yaml`.
   - *Правило:* Зафиксировать фактические версии рантаймов и ключевых библиотек (Next.js, FastAPI, Drizzle, Pydantic, pgvector и др.). При необходимости сверить актуальные сигнатуры через Context7 MCP.

3. **Аудит существующих документов (Non-Destructive Scan):**
   - Найти все существующие `README*.md`, `docs/**/*.md`, `ARCHITECTURE.md`, `CONTRIBUTING.md`.
   - Понять бизнес-цель проекта, предметную область и ключевых акторов.
   - ⚠️ **Критическое правило:** Категорически запрещено удалять или затирать уникальные инженерные документы проекта. Если в проекте уже есть `docs/architecture.md` с глубоким описанием, агент НЕ перезаписывает его, а связывает через перекрестные ссылки с `AGENTS.md`.

4. **Аудит команд сборки, линтинга и тестов:**
   - Найти реальные скрипты в `scripts` секциях `package.json` или Makefile / Justfile / Taskfile.
   - Зафиксировать команды для:
     - `typecheck` (например: `pnpm -r typecheck` или `tsc --noEmit`)
     - `lint` (например: `pnpm lint` или `ruff check .`)
     - `test` (например: `pnpm test` или `pytest tests/`)

---

### ФАЗА 2. Настройка инфраструктуры агентов (Agent Setup)

Если файлы стартер-кита еще не перенесены в целевой проект:
1. Скопировать `AGENTS.md` в корень целевого репозитория.
2. Создать симлинк `CLAUDE.md -> AGENTS.md`.
4. Скопировать недостающие шаблоны из `agent-starter-kit/docs/` в `docs/` проекта, не перезаписывая одноименные существующие файлы.

---

### ФАЗА 3. Синтез и заполнение (Synthesis Phase)

Агент формирует контент для `AGENTS.md` и вспомогательных файлов:

1. **Шапка [AGENTS.md](AGENTS.md):**
   - Название и лаконичное описание назначения проекта (2–4 емких предложения).
   - Актуализированный стек: выписать реальные рантаймы и библиотеки, обнаруженные на Фазе 1.
   - Структура каталогов монорепозитория или микросервисов.
2. **Раздел «Automated Verification Gate»:**
   - Записать точные, проверенные команды запуска линтеров, тайпчека и тестов для данного репозитория.
3. **Обновление [docs/glossary.md](glossary.md):**
   - Добавить специфичные термины доменной области, выявленные из кода и документации.
4. **Обновление [docs/architecture.md](architecture.md):**
   - Отразить границы Skeleton (общие пакеты, БД, шина) и Pluggable Modules (сервисы / фичи). Если у проекта есть своя детальная архитектурная дока — вставить ссылку на нее.
5. **Инициализация [docs/state.md](state.md):**
   - Зафиксировать текущее состояние онбординга: проект просканирован, стандарты подключены, готов к работе.

---

### ФАЗА 4. Confirmation Gate (Отчет пользователю)

Агент **НЕ завершает работу вслепую**, а выводит пользователю структурированное резюме:
1. **Тип проекта:** (например: *Turborepo монорепозиторий из 2 приложений и 3 пакетов*).
2. **Выявленный стек и рантаймы:** (краткий список).
3. **Обнаруженные команды проверки:** (команды для линтера, тестов и сборки).
4. **Статус документов:** список созданных/обновленных файлов и подтверждение сохранности оригинальной документации.
5. **Запрос подтверждения:** вопрос пользователю, готов ли он утвердить заполненный `AGENTS.md` или требуются корректировки.
